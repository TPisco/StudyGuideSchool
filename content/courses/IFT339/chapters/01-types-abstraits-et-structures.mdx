## 1. À quoi servent les structures de données

Le cours part d'un constat de génie logiciel : la façon dont les données sont
organisées décide de la qualité du logiciel. Les diapositives listent quatre
apports.

<Source file="IFT339-1-Abstraction de données (3).pdf" page={4} />

- **Organisation de la mémoire** — conception et mise en œuvre.
- **Traitement et rapidité** — efficacité des algorithmes.
- **Stockage des données** et **facilité d'utilisation**.
- Conséquences : **meilleures performances**, **plus grande évolutivité**,
  **maintenance plus facile**.

Le cours les classe en deux familles.

## 2. Le type de données abstrait

### 2.1 Définition

> Spécifications d'un ensemble d'objets de même type et d'un ensemble
> d'opérations possibles sur ces objets.

<Source file="IFT339-1-Abstraction de données (3).pdf" page={8} locator="Diapositive 8" />

C'est une **abstraction** de la structure de données : une **vue logique** d'un
ensemble de données, avec ses opérations de création, d'accès et de
modification.

### 2.2 Ce qu'un TDA dit — et ce qu'il tait

La diapositive 9 pose la frontière, et c'est elle qu'il faut retenir :

| Un TDA **spécifie** | Un TDA **ne spécifie pas** |
| --- | --- |
| le type de données contenues | la façon dont les données sont stockées |
| une description détaillée des opérations possibles sur ces données | comment les méthodes sont implémentées |

<Callout type="note" title="Le TDA est un contrat">
Le cours insiste sur cette formule : un type abstrait est un **contrat** entre
la personne qui **utilise** la structure de données et celle qui la
**développe**. Il définit la relation entre les valeurs des paramètres et le
retour des opérations. Il **dit ce que doit faire** la structure de données ;
il **ne dit pas comment le faire**. Il doit être précis et rigoureux, et
**éviter de poser des contraintes d'implantation**.
</Callout>

<Source file="IFT339-1-Abstraction de données (3).pdf" page={11} locator="Diapositives 11 à 13" />

### 2.3 Les caractéristiques à fournir

Un TDA se décrit par trois éléments :

- l'**identité** — le nom du type ;
- le **type des données**, c'est-à-dire le **domaine** ;
- les **opérations**, sous la forme `paramètres ➔ retour`.

Il est **indépendant** de la représentation utilisée pour les données, des
algorithmes utilisés pour les opérations, et du langage d'implémentation.

<Callout type="misconception" title="Erreur classique">
Croire qu'un usager peut modifier un TDA. Les notes sont explicites : c'est
**impossible**, au risque d'introduire des incohérences. L'usager consomme le
contrat, il ne le réécrit pas.
</Callout>

### 2.4 À quoi ça sert, concrètement

- Pour celui qui **développe** le type : vérifier que la réalisation respecte
  les propriétés du contrat ; cela guide la mise au point (certifications,
  tests).
- Pour celui qui **utilise** le type : connaître *a priori* le comportement
  sans connaître les détails d'implantation, et vérifier la validité de son
  utilisation.

En phase de conception, le TDA permet de **ne pas être encombré de détails
techniques**, de ne pas être influencé par les contraintes secondaires, et de
**repousser les décisions de représentation physique aux étapes ultérieures**.

<Source file="IFT339-1-Abstraction de données (3).pdf" page={12} locator="Diapositives 12 et 13" />

## 3. La structure de données

### 3.1 Définition

> Implémentation d'un TDA dans un langage donné.

Elle inclut trois choses :

1. la **représentation** des objets ;
2. l'**implémentation des algorithmes** des opérations spécifiées dans le TDA ;
3. des **opérations non visibles** par les utilisateurs (non spécifiées) et
   leur implémentation.

Les opérations **spécifiques** diffèrent en conséquence :

| Représentation | Opérations de mutation |
| --- | --- |
| `coordonnées : tableau de 2 Réels` | `modifAbs : Point2D x Réel ➔ Point2D`, `modifOrd : Point2D x Réel ➔ Point2D` |
| `rayon : Réel`, `angle : Réel` | `modifRay : Point2D x Réel ➔ Point2D`, `modifAngl : Point2D x Réel ➔ Point2D` |

<Source file="IFT339-1-Abstraction de données (3).pdf" page={18} locator="Diapositive 18" />

Les opérations **du TDA**, elles, ne bougent pas :

```
Point2D — Points dans un plan
    créer    : Réel x Réel ➔ Point2D
    créer    : Ø ➔ Point2D
    estÉgal  : Point2D x Point2D ➔ Booléen
    modifier : Point2D x Point2D ➔ Point2D
    distance : Point2D x Point2D ➔ Réel
```

Cela permet **une conception modulaire et rigoureuse**, et **l'intégration de
nouveaux types à partir des types de base**.

## 5. Programmation par type abstrait

### 5.1 Avantages et inconvénients

Le cours ne présente pas l'approche comme gratuite :

| Avantages | Inconvénients |
| --- | --- |
| Encapsulation | Efficacité |
| Abstraction | Complexité |
| Indépendance de la structure de données | Courbe d'apprentissage |
| Dissimulation d'informations | Flexibilité limitée |
| Modularité, réutilisabilité, efficacité | Coût de développement |

<Callout type="warning" title="« Efficacité » figure dans les deux colonnes">
Ce n'est pas une coquille des diapositives. L'abstraction fait gagner en
efficacité de **développement** (réutiliser un type bien conçu) et fait perdre
en efficacité d'**exécution** (couches d'indirection, opérations générales là
où un code spécialisé serait plus court).
</Callout>

<Source file="IFT339-1-Abstraction de données (3).pdf" page={20} locator="Diapositive 20" />

### 5.2 Ce que la POO ajoute

La programmation orientée objet **réalise** la programmation par type abstrait
en utilisant l'abstraction procédurale :

- **modularité** — un ensemble de types (en C++ : des *classes*) interagissant
  entre eux ;
- **encapsulation** — la représentation des données et les opérations sont
  cachées dans la définition des types ;
- **abstraction procédurale** — la description du comportement des types
  (prototypes et sémantique des opérations) est **séparée** des algorithmes des
  opérations.

L'objectif affiché est l'**intégration harmonieuse des types usagers**, en
utilisant l'architecture et les types existants, pour que le compilateur les
traite avec la même cohérence que les **types primitifs**.

<Source file="IFT339-1-Abstraction de données (3).pdf" page={24} locator="Diapositives 24 et 25" />

### 5.3 La réutilisation, en pratique

Dans l'exemple des polygones, le type `Point2D` est **réutilisé pour tous les
types de figures** — `Polygone`, `Rectangle`, `Triangle`, `Losange`, `Carré`,
`EnsemblePolygones`.

```
Polygone — Polygones dans un plan
    translation   : Polygone x Point2D ➔ Polygone
    rotation      : Polygone x Réel ➔ Polygone
    aire          : Polygone ➔ Réel
    circonférence : Polygone ➔ Réel
    affiche       : Polygone ➔ Ø
```

<Source file="IFT339-1-Abstraction de données (3).pdf" page={23} locator="Diapositive 23" />

entre l'ensemble des éléments du type et l'ensemble des représentations.

Une représentation doit aussi être choisie **en fonction de l'utilisation**
— celle avec laquelle les opérations effectivement utilisées seront les plus
efficaces.

## 7. Les types primitifs classiques

Deux familles, plus les adresses.

<Source file="IFT339-1-Abstraction de données (3).pdf" page={29} locator="Diapositives 29 et 30" />

Un **nombre à virgule flottante** est représenté à trois composantes :

$$
\text{Nombre} = \text{Signe} \times (1 + \text{mantisse}) \times 2^{\text{exposant}}
$$

Les types **composés** sont les conteneurs (`[n]` tableaux primitifs, `array`,
`string`), le style constante (`enum`), et le **pointeur**, qui contient
l'adresse d'un objet en mémoire.

### 7.1 Les deux ressources

Le cours ramène toute la suite à deux ressources :

- le **temps** — unité centrale de traitement ;
- la **mémoire (espace)** — une suite d'octets ; 1 octet = 8 bits ; l'adresse
  d'un octet est sa position en mémoire.

ces deux ressources. **Ce document n'a pas été fourni.** Le chapitre 5 utilise

## 8. Représentation des types entiers

### 8.1 Tailles dépendantes de l'architecture

Les définitions de `short`, `int` et `long` **dépendent de l'architecture** de
la machine, avec la garantie d'ordre suivante :

$$
\text{short} \le \text{int} \le \text{long}
$$

- architecture à 16 bits : `short = int = 16` ; `long = 32`
- architecture à 32 bits : `short = 16` ; `int = long = 32`

Depuis **C++11**, un système de noms lève l'ambiguïté : `[u]int[8|16|32|64]_t`
— par exemple `uint8_t` (non signés sur 8 bits), `int16_t` (signés sur 16
bits). Les constantes se suffixent : `0U`, `1L`, `1ULL`.

<Source file="Exemple TAD entier (3).pdf" page={6} />

### 8.2 Entiers non signés

Sur $n$ bits, il y a $2^n$ représentations possibles, couvrant
$[0,\ 2^n - 1]$. Chaque nombre est une somme de puissances de 2 :

$$
\text{Nombre} = b_{n-1} \times 2^{n-1} + b_{n-2} \times 2^{n-2} + \cdots + b_1 \times 2^1 + b_0 \times 2^0
$$

Sur 4 bits : $2^4 = 16$ représentations, de `0000` = 0 à `1111` = 15.

### 8.3 Entiers signés

Mêmes $2^n$ représentations, réparties différemment — l'intervalle devient
$[-2^{n-1},\ 2^{n-1} - 1]$ :

- **la moitié** pour les entiers positifs ou nuls, $[0,\ 2^{n-1} - 1]$ : ce
  sont les représentations telles que $b_{n-1} = 0$ ;
- **l'autre moitié** pour les négatifs, $[-2^{n-1},\ -1]$ : celles telles que
  $b_{n-1} = 1$.

Sur 4 bits, `0111` vaut 7 et `1000` vaut $-8$ : la valeur d'une représentation
négative se lit en retranchant $2^n$.

$$
1111 \rightarrow 1 \times 2^3 + 1 \times 2^2 + 1 \times 2^1 + 1 \times 2^0 - 2^4 = 15 - 16 = -1
$$

<Source file="Exemple TAD entier (3).pdf" page={5} />

### 8.4 L'algorithme de conversion

Pour représenter un entier positif sur $n$ bits :

```
Pour i de n-1 à 0, faire
    bi ← x / 2^i          (division entière)
    Si bi == 1
        x ← x - 2^i
```

Déroulé pour $x = 46$ sur 8 bits :

| $i$ | $x / 2^i$ | $b_i$ | nouveau $x$ |
| --- | --- | --- | --- |
| 7 | 46 / 128 = 0 | 0 | 46 |
| 6 | 46 / 64 = 0 | 0 | 46 |
| 5 | 46 / 32 = 1 | 1 | 46 − 32 = 14 |
| 4 | 14 / 16 = 0 | 0 | 14 |
| 3 | 14 / 8 = 1 | 1 | 14 − 8 = 6 |
| 2 | 6 / 4 = 1 | 1 | 6 − 4 = 2 |
| 1 | 2 / 2 = 1 | 1 | 2 − 2 = 0 |
| 0 | 0 / 1 = 0 | 0 | 0 |

D'où la représentation de 46 sur 8 bits : `00101110`.

<Source file="Exemple TAD entier (3).pdf" page={7} />

### 8.5 Inversion — le complément à deux

Pour obtenir l'opposé d'un entier sur $n$ bits, deux étapes :

1. prendre le **complément à 1** de la représentation (inverser chaque bit) ;
2. **additionner 1**.

```
  Représentation de 46      00101110
  Complément à 1            11010001
+                           00000001
  ──────────────────────────────────
  Représentation de -46     11010010
```

### 8.6 Élargir la représentation

Pour **augmenter le nombre de bits**, on **propage le bit de poids fort** sur
les nouveaux bits :

| Valeur | 8 bits | → 16 bits |
| --- | --- | --- |
| 46 | `00101110` | `0000000000101110` |
| −46 | `11010010` | `1111111111010010` |

<Callout type="misconception" title="Erreur classique">
Compléter avec des zéros lors du passage de 8 à 16 bits. Pour $-46$, cela
donnerait `0000000011010010`, soit **+210** : le signe est perdu. C'est le bit
de poids fort — et lui seul — qu'il faut recopier.
</Callout>

<Source file="Exemple TAD entier (3).pdf" page={8} />

## 9. Le TDA Entier, écrit comme un TDA

Le document d'exemple applique au type `int` lui-même la démarche du chapitre :

```
Entier
    Entiers compris entre -2^(n-1) et 2^(n-1)
    chaineB : Chaine_bin
    créer     : Chaine_dec ➔ Entier
    +         : Entier x Entier ➔ Entier
    - unaire  : Entier ➔ Entier
    -         : Entier x Entier ➔ Entier
    *         : Entier x Entier ➔ Entier
    /         : Entier x Entier ➔ Entier
```

`Entier` s'appuie sur un second TDA, `Chaine_bin`, qui porte les opérations de
bas niveau — `complément`, `décaler`, et les mêmes opérateurs arithmétiques.
C'est exactement la réutilisation vue à la section 5.3, appliquée cette fois à
un type primitif.

<Callout type="note" title="Pourquoi ce détour par le binaire dans un cours de structures de données">
Parce qu'il démontre la thèse du chapitre sur un cas où l'on croit qu'il n'y a
rien à décider : même `int` est un TDA dont la représentation a été choisie, et
ce choix a des conséquences observables — l'intervalle
$[-2^{n-1},\ 2^{n-1}-1]$ n'est pas symétrique, et le dépassement de capacité
est le prix de la bijection retenue.
</Callout>
