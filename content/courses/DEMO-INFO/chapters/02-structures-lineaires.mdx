## 1. Le problème : ranger n éléments

Il existe deux stratégies fondamentales pour stocker une suite d'éléments, et
tout le reste en découle :

1. **Les poser côte à côte** dans une zone mémoire d'un seul tenant — le
   **tableau contigu**.
2. **Les disperser** et relier chaque élément au suivant par une adresse — la
   **liste chaînée**.

Chaque stratégie rend certaines opérations gratuites et d'autres coûteuses. Il
n'y a pas de gagnant absolu ; il y a un choix à justifier.

Puisque les cases se suivent, l'adresse de la case $i$ se **calcule** :

$$
\text{adresse}(i) = \text{adresse de base} + i \times \text{taille d'un élément}
$$

C'est une multiplication et une addition, indépendamment de $i$ et de $n$ :
l'accès indexé est en $\Theta(1)$.

### 2.2 Le coût de l'insertion

Insérer en position 0 dans un tableau plein de $n$ éléments oblige à **décaler
les $n$ éléments** d'un cran vers la droite pour libérer la place.

```python
def inserer_au_debut(tableau, valeur):
    tableau.append(None)              # agrandir
    for i in range(len(tableau) - 1, 0, -1):
        tableau[i] = tableau[i - 1]   # n decalages
    tableau[0] = valeur
    return tableau
```

Coût : $\Theta(n)$. En revanche, insérer **à la fin** ne décale rien : c'est
$\Theta(1)$ (amorti, si la capacité doit parfois doubler).

<Callout type="misconception" title="Erreur classique">
Croire que `liste.insert(0, x)` en Python est aussi rapide que
`liste.append(x)`. Une `list` Python est un tableau dynamique contigu :
`insert(0, x)` décale tout et coûte $\Theta(n)$, `append(x)` coûte $\Theta(1)$
amorti. Dans une boucle de $n$ insertions en tête, l'écart est un facteur $n$.
</Callout>

## 3. La liste simplement chaînée

### 3.1 Structure

Chaque élément est un **nœud** contenant une valeur et l'adresse du nœud
suivant. Le dernier pointe vers `null`. On ne retient que l'adresse du premier
nœud, la **tête**.

<Mermaid caption="Liste simplement chaînée. Les nœuds peuvent être n'importe où en mémoire ; seul le chaînage compte." chart={`
flowchart LR
    T["tete"] --> A
    A["12 | suivant"] --> B["7 | suivant"]
    B --> C["41 | suivant"]
    C --> D["3 | null"]
    D --> N(["null"])
    style N fill:#1f2937,stroke:#6b7280,color:#9ca3af
`} />

```python
class Noeud:
    def __init__(self, valeur, suivant=None):
        self.valeur = valeur
        self.suivant = suivant

class ListeChainee:
    def __init__(self):
        self.tete = None
```

### 3.2 Les coûts s'inversent

- **Accès à l'élément $i$** : il n'y a aucun calcul d'adresse possible. Il faut
  partir de la tête et suivre $i$ pointeurs → $\Theta(n)$.
- **Insertion en tête** : créer un nœud, le faire pointer vers l'ancienne tête,
  déplacer la tête. Trois affectations, rien à décaler → $\Theta(1)$.

```python
def inserer_en_tete(self, valeur):
    self.tete = Noeud(valeur, self.tete)   # Theta(1), quel que soit n
```

<Callout type="warning" title="Le piège de l'insertion en Θ(1)">
« L'insertion dans une liste chaînée est en $\Theta(1)$ » n'est vrai que si
l'on **dispose déjà du nœud précédent**. Insérer à la position $i$ en partant
de la tête coûte $\Theta(i)$ pour s'y rendre, puis $\Theta(1)$ pour rebrancher.
Le coût total reste $\Theta(n)$ dans le pire cas.
</Callout>

## 4. Choisir : le tableau récapitulatif

Le tableau de synthèse « Tableau contigu vs liste simplement chaînée » en bas
de page donne tous les coûts. La règle de décision tient en deux lignes :

- Beaucoup de **lectures par indice**, peu de modifications → **tableau**.
- Beaucoup d'**insertions et suppressions en tête**, parcours séquentiel →
  **liste chaînée**.

<Callout type="note" title="Le coût caché des listes chaînées">
Une liste chaînée paie un pointeur (8 octets sur une machine 64 bits) par
élément, en plus de la valeur. Pour un million d'entiers de 4 octets, cela
triple la mémoire. Ses nœuds étant dispersés, chaque saut est une occasion de
défaut de cache — en pratique, un parcours de tableau est souvent plusieurs
fois plus rapide qu'un parcours de liste, à complexité identique.
</Callout>

## 5. La pile (LIFO)

Une **pile** est une structure où l'on n'accède qu'à **un seul bout** : le
sommet. Dernier entré, premier sorti — *Last In, First Out*.

Trois opérations, toutes en $\Theta(1)$ :

| Opération | Effet |
| --- | --- |
| `empiler(x)` | pose x au sommet |
| `depiler()` | retire et retourne l'élément au sommet |
| `sommet()` | lit le sommet sans le retirer |

<Mermaid caption="Cycle de vie d'une pile : le sommet est le seul point d'accès." chart={`
stateDiagram-v2
    [*] --> Vide
    Vide --> NonVide : empiler(x)
    NonVide --> NonVide : empiler(y)
    NonVide --> NonVide : depiler() si taille > 1
    NonVide --> Vide : depiler() si taille = 1
    Vide --> Erreur : depiler() sur pile vide
    Erreur --> Vide : traiter l'exception
`} />

### 5.1 Application : vérifier le parenthésage

```python
def parentheses_equilibrees(texte):
    paires = {')': '(', ']': '[', '}': '{'}
    pile = []
    for c in texte:
        if c in '([{':
            pile.append(c)                       # empiler
        elif c in paires:
            if not pile or pile.pop() != paires[c]:
                return False                     # fermeture sans ouverture
    return len(pile) == 0                        # rien ne doit rester
```

La pile est exactement la structure qu'il faut : la dernière parenthèse
ouverte est la première qui doit se fermer. Coût : $\Theta(n)$ en temps, et
$\Theta(n)$ en mémoire dans le pire cas (`((((((`).

<Callout type="misconception" title="Erreur classique">
Compter les ouvrantes et les fermantes et conclure que le texte est équilibré
si les totaux coïncident. `)( ` a une ouvrante et une fermante, et pourtant le
parenthésage est incorrect. **L'ordre compte** — c'est précisément ce que la
pile vérifie et que le comptage ignore.
</Callout>

### 5.2 Où les piles apparaissent réellement

- La **pile d'appels** : chaque appel de fonction empile un cadre ; un retour
  le dépile. Une récursion sans cas de base produit un débordement de pile.
- L'**annulation** (Ctrl+Z) : la dernière action effectuée est la première
  annulée.
- L'**évaluation d'expressions** en notation postfixée.
